06. 테스트 가이드

우연한 식탁 MVP를 비밀번호 없이, 단계별로 15분 안에 확인하실 수 있도록 정리한 안내서입니다.

접속 주소https://serendipity-table-zeta.vercel.app — 참가자 화면과 운영자 어드민(/admin)이 같은 주소 안에 있습니다.
권장 환경PC Chrome(일반 창 + 시크릿 창 1개) 또는 휴대폰 브라우저. PC에서는 앱이 휴대폰 크기 카드로 보이도록 설계했습니다.
로그인로그인 화면 아래 테스트 계정으로 바로 둘러보기의 버튼을 누르면 비밀번호 없이 들어갑니다. 이메일·비밀번호 로그인용 계정 정보는 제출 양식에 있습니다.
계정 바꾸기로그인 화면(/login)으로 돌아가 다른 버튼을 누르면 됩니다.

1. 테스트 계정 6종

버튼계정이 계정으로 볼 수 있는 장면
새로 신청할 참가자new@usangtak.test다음 일정 추천 → 신청 → 모의 결제 → 결제 완료 알림
매칭 대기 참가자user@usangtak.test결제를 마치고 매칭 결과를 기다리는 상태
확정된 참가자table@usangtak.test식탁 좌석도·식당·예약명, 단체방, 체크인, 피드백
같은 식탁 참가자table2@usangtak.test확정된 참가자와 같은 테이블 — 두 창에서 실시간 채팅
매칭 실패 참가자fail@usangtak.test실패 사유와 일정 이동·이용권 보관·환불 선택
운영자admin@usangtak.test대시보드, 매칭 모니터(진행 단계), 예외 처리함, 자동 안내·발송 등 어드민 전체

2. 먼저 해 두시면 좋은 설정 — 이메일·웹 푸시 알림

이메일 알림을 직접 받아 보시려면, 참가자 계정의 알림 이메일을 본인 이메일 주소로 바꿔 주세요.
테스트 계정 주소(@usangtak.test)는 실제 메일함이 없어서, 바꾸지 않으면 메일을 받을 곳이 없습니다.
  1. 메일을 받아 볼 참가자 계정으로 로그인합니다. 가장 확인하기 쉬운 계정은 새로 신청할 참가자입니다(결제 완료 메일).
  2. 홈 화면 아래쪽 내 프로필·알림 설정을 누릅니다.
  3. 알림 영역의 알림 받을 이메일 (선택) 칸에 본인 이메일을 입력합니다.
  4. 그 아래 이메일 종류 버튼(결제 완료 · 매칭 확정 · 매칭 실패 · 행사 1일 전 · 환불 완료)이 켜져 있는지 확인합니다.
  5. 맨 아래 저장하기를 누릅니다. "저장했어요."가 보이면 끝입니다.
언제 오나요알림이 생기고 1분 안에 자동으로 발송됩니다. 바로 보내려면 운영자 › 자동 안내·발송 › 대기 중인 메시지 지금 보내기를 누르세요.
보낸 사람"우연한 식탁"(Gmail 발송). 제목은 [우연한 식탁] …으로 시작합니다. 받은편지함에 없으면 스팸함도 확인해 주세요.
발송 기록운영자 › 자동 안내·발송의 발송 이력에서 받는 사람·성공/실패·시도 횟수를 볼 수 있습니다.
웹 푸시같은 화면의 웹 푸시 스위치를 켜고 브라우저 알림 권한을 허용한 뒤 테스트 알림 보내기를 누르세요. 아이폰은 Safari에서 홈 화면에 추가한 앱에서만 푸시를 받습니다.

3. 추천 시연 순서 (약 15분)

① 신청과 모의 결제 새로 신청할 참가자

  1. (2장처럼 알림 이메일을 바꿔 둡니다.)
  2. 홈 › 참가 이력 · 다음 일정 추천 › 다음 식탁 추천에서 추천 일정으로 신청합니다. 저장된 프로필이 미리 채워져 있습니다.
  3. 결제 화면에서 모의 결제를 합니다(실제로 돈이 나가지 않습니다).

확인 포인트: "신청과 결제가 끝났어요" 화면, 홈 상태 변경, 알림함(오른쪽 위 종) 결제 완료 알림, 입력한 메일함의 결제 완료 메일

② 자동 매칭 실행 운영자

  1. 어드민 › 매칭 모니터에서 11/5 회차를 고릅니다.
  2. 진행 단계 패널의 ① 13명 만들기 → ② 즉시 실행을 차례로 누릅니다.

확인 포인트: 테이블 2개 확정, 다른 지역으로 재배치 2명, 나이 차이로 실패 1명 — 실행 기록에 각각의 사유가 남습니다.

③ 확정 안내와 식탁 확정된 참가자

  1. 홈의 티켓 카드(날짜·식당·시간)를 누릅니다.
  2. 식탁 좌석도·식당 주소·예약명·식사 조건을 확인하고, 단체방으로 들어갑니다.

확인 포인트: 단체방에 자동으로 올라온 확정 안내·큐레이션·식사 조건 메시지

④ 실시간 단체방 확정된 참가자 + 같은 식탁 참가자

  1. 시크릿 창을 하나 열어 같은 주소에 접속하고 같은 식탁 참가자로 로그인합니다.
  2. 두 창에서 같은 단체방에 들어가 메시지를 주고받습니다.

확인 포인트: 새로고침 없이 상대 창에 메시지가 바로 나타남

⑤ 행사 당일 흐름 운영자 → 확정된 참가자

  1. 어드민 › 매칭 모니터에서 10/22 회차를 고릅니다.
  2. 진행 단계 버튼을 순서대로 누릅니다: 리마인드 보내기 → 행사 시작 → 체크인 채우기 → 행사 종료 → 피드백 채우기 → 노쇼 확정. 이미 끝난 단계는 건너뛰셔도 됩니다.
  3. 중간에 확정된 참가자 창으로 돌아가 단체방과 체크인 버튼을 확인합니다.

확인 포인트: 단체방의 전날 리마인드, 대화 주제 3개와 아이스브레이킹, 체크인, 행사 종료 후 피드백 요청

⑥ 매칭 실패 후 선택 매칭 실패 참가자 → 운영자

  1. 홈에서 실패 사유와 대체 일정 안내를 확인합니다.
  2. 일정 이동 · 이용권 보관 · 환불 중 하나를 고릅니다(환불을 고르면 환불 완료 알림·메일).
  3. 선택 전이라면 운영자 대시보드의 선택 대기 참가자에서 이 사람을 바로 찾을 수 있습니다.

⑦ 운영자 화면 둘러보기 운영자

대시보드(핵심 지표·할 일) · 회차 관리 · 식당·재고 · 신청자 목록 · 결제·환불 내역 · 테이블 조회 · 참석·노쇼 현황 · 자동 안내·발송(메시지 템플릿 수정, 발송 이력) · 예외 처리함 · 신고·제재. 신청자·테이블은 CSV로 내려받을 수 있습니다.

4. 알아 두시면 좋은 점

시연 장면 고정시연 회차(10/22 · 10/29 · 11/5)는 자동 진행을 멈춰 두어 시간이 지나도 장면이 그대로입니다. 진행 단계 버튼으로만 움직입니다.
처음 상태로 되돌리기매칭 모니터에서 되돌리기 → 되돌리기 확인을 누른 뒤 다시 즉시 실행을 누르면 매칭 직후 상태로 돌아갑니다. 실패 참가자의 이동·보관·환불 선택도 함께 원래대로 돌아갑니다.
계정을 여러 분이 함께 쓸 때신청·결제·실패 해결처럼 한 번 처리한 일은 그 상태로 남습니다. 앞서 다른 분이 진행하셨다면 결과 화면부터 보일 수 있습니다.
같은 메일은 한 번만같은 알림이 두 번 가지 않도록 막아 두었습니다. 예를 들어 리마인드 메일은 그 회차에서 처음 한 번만 발송됩니다.
운영자 권한 범위개인정보 보호를 위해 운영자도 참가자끼리의 단체방 대화 내용은 볼 수 없고, 운영 안내 발송 수만 봅니다.
모의 처리결제·환불은 시연용 모의 처리이며 실제 돈이 오가지 않습니다. 문자·카카오 알림톡은 사업자 인증이 필요해 범위에서 제외했습니다.
