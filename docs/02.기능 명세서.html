1. 문서 개요

항목내용
목적요구 분석서의 요구사항 49건을 구현 단위 기능 86건으로 나누고, 화면 27개와 업무 흐름 9개를 정의해 구현·테스트의 기준으로 삼는다.
구현 환경참가자 모바일 우선 반응형 웹·PWA + 운영자 웹 어드민(/admin), 하나의 Next.js 앱. DB·인증·실시간·스케줄러는 Supabase(Postgres·Auth·Realtime·pg_cron), 배포는 Vercel, 이메일은 Gmail SMTP (ADR-001). 매칭 엔진은 화면·DB와 분리된 순수 함수 모듈이며 DB 함수로 멱등 실행한다.
번호 체계R-xx 요구사항(01 문서), F-xx 기능(이 문서 3장), S-xx 화면(5장), FL-x 순서도(6장). 추적은 R → F → S 순서이고 7장에서 한 번에 확인한다.
차수차수는 구현하는 순서다. 1차에서 계정·신청·결제와 운영 기본 설정을, 2차에서 자동 매칭·확정·안내와 매칭 실패 해결을, 3차에서 피드백·취소·노쇼와 운영 조회 화면을, 4차에서 지표와 CSV 내보내기를 만든다. 추가 기능은 필수 흐름을 처음부터 끝까지 시연할 수 있게 된 뒤에 진행하고, 날짜별 일정은 워크스페이스 계획을 따른다.
이 문서에 없는 것테이블·컬럼·제약은 데이터 정의서에서 정의한다. 이 문서의 상태값·설정값은 그 정의의 입력이다.

2.3 상태값

상태는 하나로 합치지 않고 4종을 따로 저장한다(요구 분석서 5.3). 값이 바뀔 때마다 시각·주체(참가자·운영자·시스템)·원인·이전 값을 이력에 남기고, 어떤 기능이 어떤 값을 바꾸는지는 4.5에 정리했다.

2.4 설정값

2.5 화면 공통

구분규칙
입력 오류필수 값이 비거나 형식이 틀리면 저장하지 않고 해당 입력창 가까이에 이유를 표시한다. 입력한 값은 지우지 않는다.
중복 제출처리 중에는 실행 버튼을 비활성화한다. 결제·환불·취소는 서버에서도 한 번만 처리한다.
빈 상태목록이 비면 영역을 안내 문구로 바꾸고, 다음 행동(신청하러 가기 등)을 함께 보여 준다.
불러오기 실패데이터가 없는 경우와 구분해 안내하고 다시 시도 버튼을 제공한다.
대기·실패 상태실패·대기 상태에서도 다음 행동을 같은 화면 안에서 고를 수 있어야 한다.
구현 범위 일치구현하지 않은 기능의 메뉴·버튼은 화면에 내보내지 않는다. 보이는 메뉴는 모두 동작하는 화면으로 이어진다.
화면 구성반응형 웹이다. 참가자 화면은 휴대폰 1열에서 시작해 태블릿·PC에서는 2열로 넓힌다(예: 홈은 상태 카드와 다음 일정을 나란히, 단체방은 공지와 대화를 나란히). PWA로 홈 화면에 설치해 앱처럼 쓸 수 있다. 운영자 화면은 PC 기준 표·필터 중심이고, 휴대폰에서는 대시보드 확인까지 지원한다.

2.6 자동 처리 공통

구분규칙
실행 경로스케줄러 실행과 시연 패널 즉시 실행은 같은 함수를 호출한다.
멱등성작업마다 키(회차·단계)를 두고, 같은 키의 재실행은 이전 결과를 유지한다. 중복 테이블·환불·단체방을 만들지 않는다.
필수 조건테이블을 만들기 위해 완화하지 않는다. 확정 직전에 다시 검증한다. 이미 확정된 테이블이 행사 당일 줄어든 경우는 다시 확정하는 것이 아니므로 4.4를 따른다.
실패 처리자동 재시도 → 대체 후보 탐색 → 모두 실패할 때만 예외 처리함. 운영자는 예외만 처리한다.
참가자 선택일정 이동·보관·환불은 시스템이 임의로 정하지 않고 참가자가 고른다.
알림 발송모든 알림은 DB에 먼저 기록(앱 내 알림)하고, 웹 푸시·이메일은 채널 어댑터가 참가자 설정에 따라 보낸다. 정식 운영에서는 어댑터를 추가해 알림톡·자체 도메인 메일을 붙인다.
외부 연동PG 결제, 문자·카카오 알림톡, 외부 예약은 연동하지 않는다. 결제·환불은 상태 전환으로 처리한다. 카카오톡 단체방은 공개 API가 없고 PRD가 앱 내 단체방을 요구하므로 앱 안 실시간 단체방으로 대신한다.

5.3 화면 이동

  1. 로그인(S-01) → 처음이면 프로필 작성(S-02) → 모집 일정·지역 선택(S-03) → 이용권·결제(S-04) → 홈(S-05).
  2. 홈(S-05)은 상태에 따라 한 곳으로 이어진다 — 매칭 실패는 S-06, 확정은 S-07(→ 단체방 S-08), 행사 후는 S-09, 취소·불참은 S-12.
  3. S-09 제출 후 참가 이력·다음 일정 추천(S-10)에서 S-03으로 재신청한다.
  4. 알림함(S-11)은 모든 참가자 화면의 머리글에서 열고, 각 알림은 관련 화면(S-05~S-09)으로 이동한다.
  5. 지난 모임 후기(S-14)와 FAQ·문의(S-15)는 추가 기능이며, 구현하면 홈 하단 메뉴에서 연다.
  6. 운영자는 로그인 후 대시보드(S-21)에서 시작하고, 건수를 눌러 예외 처리함(S-26)·참석 관리(S-29)·피드백 관리(S-30)로 이동한다.
