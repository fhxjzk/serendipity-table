4. 결정

A안 — Next.js(App Router) + TypeScript + Supabase(Postgres·Auth·pg_cron) + Vercel로 확정한다.
  1. 자동매칭(배점 25)의 핵심인 마감 시각 자동 실행을 별도 서비스 없이 해결한다. DB 예약 실행이 1분마다 매칭 API를 호출하고, 운영자 화면의 "지금 마감 실행" 버튼도 같은 API를 쓴다.
  2. 앱 하나·배포 하나로 참가자 모바일 웹과 운영자 어드민을 함께 운영해 1인 개발 부담을 줄인다.
  3. 정식 운영으로 그대로 이어진다. 유료 요금제 전환과 보안 점검만으로 초기 운영이 가능하고, 데이터는 표준 Postgres라 이전이 쉽다.

4.1 알림·단체방 구성 (v1.1 추가)

기능 명세서 검토에서 PRD INF-01·INF-07이 "앱 푸시"를 요구하는 것을 확인해, 앱 내 알림함만 두던 v1.0 결정을 아래처럼 바꿨다.

대상결정이유
단체방Supabase Realtime으로 새 메시지를 바로 반영한다. 연결이 끊기면 30초 새로고침으로 대신한다.Vercel 서버 함수는 소켓을 유지할 수 없지만, Realtime은 Supabase가 연결을 관리해 별도 서버가 필요 없다. RLS를 그대로 적용할 수 있다.
앱 내 알림모든 알림을 DB에 먼저 기록하고 알림함에 보여 준다.발송 결과와 관계없이 남는 기록(원장) 역할
웹 푸시PWA(manifest·서비스 워커) + Web Push(VAPID 키). 구독 정보를 저장하고 서버에서 발송한다.앱스토어 앱 없이 PRD의 앱 푸시를 충족한다. 아이폰은 홈 화면에 설치한 뒤(iOS 16.4 이상) 받을 수 있다.
이메일Gmail SMTP(발송 전용 계정, 보낸 사람 이름 "우연한 식탁"). 중요 알림 5종만 참가자 설정에 따라 보낸다.도메인 없이 무료로 실제 네이버·Gmail 주소에 보낼 수 있다. 앱 비밀번호는 환경변수로만 관리한다.
문자·카카오 알림톡이번 범위에서 제외한다.알림톡은 사업자 인증을 마친 비즈니스 채널과 템플릿 사전 심사가 필요하고, 문자는 발신번호 등록과 비용이 든다.
카카오톡 단체방연동하지 않는다.단체 채팅방을 만드는 공개 API가 없고, PRD INF-04와 완료 조건은 앱 내 단체방을 요구한다.

발송은 채널 어댑터(앱 내·웹 푸시·이메일)로 분리해, 정식 운영에서 자체 도메인 메일(Resend 등)이나 알림톡을 어댑터 추가만으로 붙인다.

5.2 핵심 설계 원칙

  • 매칭 엔진은 순수 함수로 만든다. 입력(후보·설정)과 출력(테이블·배치 사유)만 갖고 DB와 화면을 모른다. 단위 테스트로 "필수 조건 위반 확정 0건, 4명 미만 확정 0건"을 검증한다.
  • 멱등 실행. 회차별 매칭 실행에 고유 키를 두고 UNIQUE 제약으로 중복 실행을 막는다. 확정·환불·단체방 생성은 한 트랜잭션(DB 함수)에서 처리한다.
  • 상태 4종 분리. application_status · payment_status · match_status · attendance_status를 각각 저장하고, 변경마다 이력을 남긴다.
  • 권한은 DB에서 막는다. 행 단위 보안(RLS)으로 참가자는 본인 데이터만, 운영자 역할만 전체를 조회한다. 다른 참가자의 개인정보와 상세 점수는 노출하지 않는다.
  • 단체방은 Realtime, 알림은 채널 어댑터. 메시지와 알림은 DB에 먼저 기록하고, 화면 반영은 Realtime 구독으로, 바깥 발송은 앱 내·웹 푸시·이메일 어댑터로 한다. 연결이 끊기면 30초 새로고침으로 대신한다. (v1.0의 "주기적 새로고침·앱 내 알림만" 결정을 v1.1에서 변경)
  • 결제는 교체 가능한 어댑터. 지금은 모의 결제, 정식 운영에서 PG(토스페이먼츠 등)로 바꿀 때 어댑터만 교체한다.

7. 위험과 대응

위험영향대응
Supabase 무료 DB가 7일 무사용 시 일시정지심사 기간(10/22~10/28)에 링크가 동작하지 않음Vercel 크론으로 하루 1회 DB 조회, 심사 기간 중 매일 접속 확인
Vercel 무료 크론은 하루 1회만 실행마감 시각 매칭을 맡길 수 없음매칭 실행은 pg_cron이 담당하고, Vercel 크론은 유지용으로만 사용
RLS 설정 오류다른 참가자 정보 노출테이블별 정책 작성, 다른 계정으로 접근 시험을 테스트 체크리스트에 포함
서버 함수 실행 시간 제한대규모 매칭 중단회차 단위로 실행, 294명 가상데이터로 실행 시간 측정
Next.js 서버 기능 학습 시간일정 지연매칭 엔진을 프레임워크와 무관한 TypeScript 모듈로 작성해 영향 범위를 줄임
아이폰 웹 푸시는 홈 화면 설치 후에만 동작일부 참가자가 푸시를 받지 못함앱 내 알림·이메일로 보완하고, 설치 안내 배너를 띄운다
Gmail 발송 한도·스팸함 분류메일 미도착중요 5종만 발송, 시연 전 네이버·Gmail 수신 시험, 앱 비밀번호는 환경변수로만 관리
Realtime 연결 끊김·단체방 권한 누락메시지 지연·다른 테이블 노출30초 새로고침 대체, 단체방 메시지 RLS를 같은 테이블 참가자로 제한하고 다른 계정으로 접근 시험
무료 요금제 조건 변경위 대응 무효화계정 생성 시 현재 조건을 확인하고 결과를 기록
