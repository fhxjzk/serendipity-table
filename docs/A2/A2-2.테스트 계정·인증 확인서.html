1. 테스트 계정

구분아이디role로그인 후 첫 화면볼 수 있는 데이터
운영자admin@usangtak.testOPERATOR/admin 운영자 어드민모든 테이블 조회·수정
참가자user@usangtak.testPARTICIPANT/home 참가자 홈본인 프로필·신청·알림, 공개 기준정보(회차·코드값 등), 본인 테이블 단체방

비밀번호는 문서에 적지 않는다. 시드 스크립트(npm run seed)가 환경 변수 값으로 계정을 만들고, 제출 시 Blaybus Output 탭에만 기재한다. 가상데이터 응답자 294명도 seedNNN@usangtak.test 계정이 있으나 무작위 비밀번호라 로그인용이 아니다.

2. 구현 내용

구분내용파일
로그인이메일·비밀번호 로그인(Supabase Auth). 실패 시 계정 존재 여부를 드러내지 않는 같은 문구 표시src/app/login/
세션 유지모든 요청에서 인증 쿠키를 갱신하고, 로그인하지 않은 사용자는 /login?next=원래경로로 보냄src/proxy.ts
역할 분기프로필의 role을 서버에서 확인해 운영자는 /admin, 참가자는 /home으로. 다른 역할의 화면에 들어오면 자기 화면으로 돌려보냄src/lib/auth.ts
DB 권한44개 테이블 모두 RLS 사용, 정책 70개. 운영자 판별 함수 is_operator(), 단체방 구성원 판별 is_room_member(). 참가자는 본인 행만, 결제·매칭·상태 변경은 서버에서만 처리supabase/migrations/…_rls_policies.sql
