우연한 식탁 MVP · 구현 결과서 · A4. 참가자 앱

매칭 실패 시 일정 이동·이용권 보관·환불 선택 화면과 처리 구현

A4-2
워크상태 확인·실패 해결 3가지 선택 처리
관련 기능F-17 홈 상태 표시 · F-18 실패 사유·대체 일정 안내 · F-19 대체 일정 이동 · F-20 이용권 보관 · F-21 환불(모의) (02.기능 명세서 번호)
목표매칭에 실패한 참가자가 운영자에게 연락하지 않고도 스스로 다음 행동을 고를 수 있게 한다.

구현 내용

  • 홈에서 내 신청 상태(결제 대기·매칭 대기·확정·실패·완료)를 단계 표시로 보여 준다.
  • 실패 시 사유와 함께 대체 일정을 안내한다.
  • 세 가지 중 하나를 선택: ① 대체 일정으로 이동 ② 이용권 보관(다음 신청에 사용) ③ 환불(모의).
  • 선택은 DB 함수에서 한 번만 처리되고(중복 선택 방지), 환불 시 환불 완료 알림이 간다.
  • 아직 선택하지 않은 참가자는 운영자 대시보드 ‘선택 대기 참가자’에 모여 보인다.

코드 위치

  • web/src/app/(participant)/applications/[id]/resolve/
  • web/src/app/(participant)/home/page.tsx
  • supabase/migrations/…000500_resolve_failure.sql
