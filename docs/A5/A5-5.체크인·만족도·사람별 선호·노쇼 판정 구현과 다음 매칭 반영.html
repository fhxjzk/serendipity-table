체크인·만족도·사람별 선호·노쇼 판정 구현과 다음 매칭 반영

A5-5
워크체크인·만족도·사람별 선호 수집 후 매칭 반영
관련 기능F-46 체크인 · F-47 만족도 · F-48 사람별 선호 · F-49 신고·차단 · F-53~56 노쇼 후보·보정·확정·패널티 (02.기능 명세서 번호)
목표모임이 끝난 뒤의 기록이 다음 매칭을 더 좋게 만든다.

구현 내용

  • 행사 시간에 체크인 버튼. 행사 종료 시 체크인하지 않은 사람은 노쇼 후보가 된다.
  • 참가자는 알림을 받고 이의 제기 가능 → 운영자가 참석 인정 또는 노쇼 확정. 확정 시 횟수에 따라 패널티를 차등 기록.
  • 피드백: 만족도·재참가 의향 + 같은 테이블 사람별 ‘다시 만나고 싶음 / 불편함’ + 신고.
  • ‘불편함’·신고는 다음 매칭에서 같은 테이블 금지, ‘다시 만나고 싶음’은 우선 고려로 반영된다.

코드 위치

  • web/src/app/(participant)/applications/[id]/feedback/, noshow/, event-actions.ts
  • supabase/migrations/…000700_event_feedback.sql
